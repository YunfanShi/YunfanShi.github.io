状态：实施中

范围：今日学习中心、一键学习会话、错题复习、AI 自适应计划、可靠提醒、Companion 内容处理、周复盘

## 1. 最终目标

把当前彼此独立的学习计划、番茄钟、QuizWise、词汇、考试倒计时、Companion 和 AI 助手连接成以下闭环：

```text
收集资料/设置目标
        ↓
生成今日计划
        ↓
开始学习会话（任务 + 计时 + 资料）
        ↓
刷题与记录结果
        ↓
错题进入间隔复习
        ↓
每日/每周复盘并调整下一轮计划
```

完成后的核心体验：用户打开首页即可知道今天该做什么，点击一次开始学习，系统自动记录投入与结果，并根据错题、考试日期和历史执行情况生成下一步建议。

## 2. 实施原则

1. 保留现有 Legacy Bridge；本轮只在必要位置增加数据适配，不整体重写旧页面。
2. 不创建一个承载所有业务的万能表。优先给现有表增加明确的外键，再为错题、计划和提醒建立职责单一的新表。
3. 登录用户使用 Supabase；游客继续 local-first，登录后通过现有同步机制迁移。
4. 所有 `public` 新表必须启用 RLS，策略同时包含所有权判断；迁移中显式授予所需 Data API 权限。
5. AI 只负责分析、推荐和自然语言交互；日期、优先级、间隔复习、统计等确定性逻辑必须由 TypeScript/SQL 实现。
6. 每一阶段独立可发布、可回滚，并包含迁移、功能、测试和文档。

## 3. 分阶段路线

### Phase 0：基线修正与领域层（v3.17.0-alpha）

目标：先修复会污染后续数据的现有问题，并建立可测试的业务计算层。

工作项：

- 修正首页“今日进度”使用累计任务完成率的问题。
- QuizWise 保存真实的开始时间、完成时间和游客练习时长。
- 统一日期边界处理，所有“今天”按用户时区计算，不依赖服务器默认时区。
- 新增纯函数领域模块：
  - `src/lib/learning/prioritization.ts`
  - `src/lib/learning/review-schedule.ts`
  - `src/lib/learning/timezone.ts`
  - `src/lib/learning/metrics.ts`
- 为上述逻辑使用现有 `node:test` 测试体系增加单元测试。

验收：

- 首页今日指标只统计今日范围。
- 游客和登录用户的 Quiz 时长均准确。
- 上海时区跨午夜、夏令时地区跨日等边界有自动化测试。

### Phase 1：任务与学习会话打通（v3.17.0）

目标：在任意学习任务上点击一次即可进入可追踪的专注会话。

数据变更：

- 扩展 `study_tasks`：`subject`、`estimated_minutes`、`priority`、`scheduled_at`、`completed_at`。
- 扩展 `focus_tasks`：增加可空 `study_task_id` 外键，保留现有独立番茄任务兼容性。
- 扩展 `focus_sessions`：增加 `study_task_id`、`planned_seconds`、`outcome`、`session_note`。
- 为用户、日期、任务关联建立索引。

产品功能：

- 学习任务新增“开始学习”。
- 启动时可选择 25/45/60 分钟、相关资料和专注音乐。
- 学习结束后记录：完成、部分完成、被打断，以及简短备注。
- 完成学习任务时同步结束关联的番茄任务；反向操作不自动完成学习任务，避免误判。
- 番茄钟页面可以筛选“来自学习计划”的任务。

验收：

- 从学习计划启动的会话可在番茄钟和首页同时看到。
- 会话结束后统计仅增加一次；重复提交具备幂等保护。
- 删除学习任务不会删除历史会话，只清空关联。

### Phase 2：今日学习中心（v3.18.0）

目标：把 `/dashboard` 从模块导航页升级成每天可执行的控制台。

首页区块：

- “下一步”：系统推荐的一个任务及推荐原因。
- 今日任务：计划中、已完成、逾期。
- 今日复习：到期词汇和错题数量。
- 最近考试：倒计时和风险提示。
- 今日专注：目标、实际时间、连续学习天数。
- 继续上次学习：恢复未结束 Quiz 或学习会话。
- 快速收集：新任务、粘贴题目、保存链接。

实现：

- Server Component 并行获取聚合数据。
- 交互按钮使用 Server Actions；不为页面内写操作额外建立 Route Handler。
- 把排序规则放进 `prioritization.ts`，AI 只生成解释，不决定基础排序。
- 无数据时提供可执行的新手引导，而不是空统计卡。

验收：

- 首页首次加载不存在串行请求瀑布。
- 任何首页任务都能在两次点击内开始学习。
- 游客模式有等价的本机体验。

### Phase 3：错题本与间隔复习（v3.18.0）

目标：让 QuizWise 的错误形成长期复习队列。

新表：

- `review_items`
  - 关联 `quiz_question_id`
  - `subject`、`knowledge_point`、`error_type`
  - `status`、`next_review_at`、`interval_days`、`ease_factor`、`streak`
- `review_attempts`
  - 关联复习项和可选 Quiz 会话
  - 保存作答结果、耗时和复习时间

产品功能：

- 错题自动进入错题本，允许用户撤销。
- AI 标注知识点与错误原因，用户可修改。
- 复习算法首版采用确定性的简化 SM-2；参数有完整测试。
- 支持“原题重做”和“生成变式题”。
- 新增 `/review`：今日待复习、薄弱知识点、已掌握项目。
- Quiz 结果页显示“下一次复习时间”。

验收：

- 错题只创建一个活跃复习项，不重复入库。
- 连续答对会延长间隔，答错会缩短间隔。
- AI 服务不可用时，原题复习仍能完整工作。

### Phase 4：AI 自适应日计划（v3.19.0）

目标：根据真实数据生成可解释、可编辑的每日计划。

新表：

- `daily_plans`：日期、可用分钟、状态、生成依据摘要。
- `daily_plan_items`：来源类型与来源 ID、排序、计划分钟、完成状态、推荐原因。

输入信号：

- 考试日期和教学大纲完成度。
- Mock/Quiz 成绩和错题到期情况。
- 词汇复习积压。
- 未完成及逾期任务。
- 最近七天专注时间和计划兑现率。
- 用户当天可用时间、固定日程和休息偏好。

规则：

- TypeScript 先计算候选任务、硬性约束和基础分数。
- AI 负责拆分任务、生成推荐理由及在约束内优化顺序。
- AI 输出必须经过 schema 校验；无效或超时则使用确定性计划。
- 用户确认后才写入日计划和日程。

验收：

- 计划总时长不超过用户可用时间。
- 固定日程不发生重叠。
- 每个推荐项都能追溯到具体任务、复习项或考试目标。
- 用户调整后的偏好会影响下一次生成，但不会覆盖明确固定项。

### Phase 5：可靠提醒中心（v3.19.0）

目标：提醒不再依赖页面内 `setTimeout`，关闭标签页后仍可恢复和同步。

新表：

- `reminders`：来源、标题、计划时间、时区、状态、稍后提醒时间、通知渠道。
- 可选 `push_subscriptions`：仅在启用 Web Push 后保存订阅信息。

产品功能：

- 任务、考试、错题复习自动建议提醒。
- 通知中心支持完成、忽略、稍后 10/30/60 分钟。
- 提醒在多设备间同步，发送动作具备幂等键。
- 设置页增加勿扰时段和默认提前量。
- 首版提供站内持久提醒和 PWA 本地通知；服务端 Web Push 在部署密钥和调度能力确认后启用。

验收：

- 刷新或重新打开应用后提醒仍存在。
- 同一提醒不会在同一设备重复发送。
- 时区变化后未来提醒保持用户期望的当地时间。

### Phase 6：Companion 内容处理流水线（v3.20.0）

目标：把“稍后学习”从链接收藏变成可执行的学习输入箱。

数据变更：

- 扩展 `companion_learning_queue`：`summary`、`processed_at`、`converted_type`、`converted_id`。
- 不新增重复的收藏表。

产品功能：

- 每条链接可转换为：学习任务、日计划项、Quiz 输入、词汇、归档。
- AI 可生成摘要、建议学科和预计阅读时间。
- 相同 URL 去重；保留不同设备的来源信息。
- 批量整理同主题链接，并允许用户确认后创建任务。
- 首页展示未处理收集箱数量。

验收：

- 转换操作具备幂等性，不会重复创建目标对象。
- AI 不可用时仍可手动转换和归档。
- 恶意标题或网页内容不会被当成系统指令执行。

### Phase 7：每日/每周复盘与全局助手升级（v3.20.0）

目标：利用闭环数据给出行动建议，而不只是展示图表。

功能：

- 每日复盘：计划兑现率、专注时间、完成内容、主要卡点。
- 每周复盘：按学科投入、成绩趋势、复习积压、下周风险。
- “计划时间 vs 实际时间”偏差分析。
- AI 助手新增原生工具：
  - 创建/调整真实学习任务
  - 开始学习会话
  - 查询和执行今日计划
  - 查看/完成错题复习
  - 创建持久提醒
  - 处理 Companion 收集箱
- 写操作继续走现有同意流程，并调用 Server Actions，而不是只修改 localStorage。

验收：

- 报告中的数字可由数据库查询复算。
- AI 建议明确说明依据，不虚构不存在的数据。
- 助手创建的数据能立即在对应原生页面出现。

## 4. 建议数据关系

```text
study_plans
  └─ study_tasks
       ├─ focus_tasks（可选的一对一映射）
       ├─ focus_sessions（历史投入）
       └─ daily_plan_items

quiz_sessions
  └─ quiz_questions
       └─ review_items
            └─ review_attempts

companion_learning_queue
  └─ converted_type + converted_id

reminders
  └─ source_type + source_id
```

不使用跨表数据库外键表示 `source_type/source_id` 多态关系；应用层必须校验所有权，并为每种来源提供测试。

## 5. 发布与兼容策略

- 新功能先通过现有 BETA 权限开放，数据库迁移保持向后兼容。
- 新增列全部先可空或带安全默认值；完成数据回填后再考虑收紧约束。
- Legacy 页面继续读取原键；适配层将关键写入同步到新模型。
- 每个阶段部署前执行：`npm run verify`。
- 涉及数据库阶段额外执行迁移列表检查、测试查询和安全顾问检查。
- 不覆盖当前正在开发的自动 Web Sync/LWW 改动；如涉及相同文件，等该改动稳定后再集成。

## 8. 完成定义

只有满足以下条件，整项计划才算完成：

- 六项核心功能全部可用于游客和登录用户，差异有清晰说明。
- 从首页开始一次学习，到产生结果、错题、复习计划和周报的完整流程验证通过。
- 数据库迁移、RLS、Data API 权限和跨用户隔离验证通过。
- 离线与多设备同步不会造成重复会话、重复错题或重复提醒。
- AI 不可用时，所有核心确定性功能仍可使用。
- `npm run verify` 通过，README、帮助中心和数据导出范围同步更新。

## 9. 第一批实际改动

实施从 Phase 0 开始，首个提交只包含：

1. 今日指标与 Quiz 时长修正。
2. 领域纯函数和测试。
3. 第一份任务/专注关联迁移。
4. 学习任务“开始学习”的最小纵向流程。

这批完成并验证后，再进入首页重构，避免同时改动过多核心页面。
