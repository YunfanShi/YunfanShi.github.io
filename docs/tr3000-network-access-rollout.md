## 已准备的站点能力

- 公开登记页：`https://jackyun.top/network-access`
- 后台管理页：`https://jackyun.top/admin/network`
- 登记字段：姓名/常用称呼、关系、设备备注，以及路由器可选提供的局域网 IP、MAC、NAS ID。
- 不收集 Wi-Fi 密码、短信验证码、付款信息或浏览内容。
- 后台可设置用户分级、TR3000 备注、限速/解除限速/阻断策略和上下行速率。
- 所有动作默认只进入“待应用”队列；没有任何云端代码会自动登录 TR3000。

## 关键技术边界

普通网页无法读取客户端 MAC 地址，也无法可靠读取 NAT 后的局域网 IP。只有以下来源可以提供可信映射：

1. TR3000 在重定向 URL 中附带 MAC/IP 参数；
2. 受信任的局域网桥接程序读取 DHCP/邻居/QoS 表；
3. 管理员在 TR3000 设备列表中手动匹配。

当前页面兼容这些常见参数别名：

- MAC：`client_mac`、`clientmac`、`mac`、`sta_mac`
- IP：`client_ip`、`clientip`、`ip`、`sta_ip`
- NAS：`nas_id`、`nasid`、`router_id`

TR3000 的 `HotspotSystem` 模板是否会附带这些参数需要用一台测试手机验证。若不附带，登记仍会保存姓名，但后台会明确显示“缺少完整 IP/MAC”，禁止生成可应用动作。

## 安全上线顺序

1. 在 Supabase 应用 `20260824153450_network_access_registry.sql`。
2. 部署站点，验证 `/network-access` 能登记、`/admin/network` 仅管理员可读。
3. 用测试 URL 验证参数映射，例如：
   `https://jackyun.top/network-access?client_ip=192.168.10.25&client_mac=AA-BB-CC-DD-EE-FF&nas_id=tr3000-main`
4. 在 TR3000 中只选择一个测试 SSID；强制主页 URL 填 `https://jackyun.top/network-access`。
5. 保持“保存&应用”未点击，先截图复核本地网段、SSID 和 URL。
6. 获得明确确认后才保存，并用一台非管理员设备测试登记、关闭页面、重新连接和租用时间到期行为。
7. 验证后台姓名、IP、MAC 与 TR3000 在线设备一致，再手动应用一条低风险 QoS 规则。
8. 验证限速和解除限速，最后再扩大到两个 SSID。

## 自动联动的第二阶段

不建议把 `192.168.10.1` 管理页、SSH 或 LuCI API 直接暴露到公网。安全方案是在局域网内运行一个最小权限桥接程序：

1. 只出站连接 `jackyun.top`，领取已审核的待应用动作；
2. 校验 MAC、速率范围、动作版本和一次性 ID；
3. 通过厂商支持的本地接口应用 QoS/MAC 过滤；
4. 回写成功/失败、路由器配置摘要和时间；
5. 凭据仅保存在局域网设备，不进入浏览器、数据库记录或 Git。

若固件没有稳定的受支持 API，保留人工应用，不通过抓取 LuCI 私有接口做脆弱自动化。

## 阿里云与新域名迁移

- 所有站点链接使用相对路径；新域名只需调整 `NEXT_PUBLIC_SITE_URL`、DNS、TLS 和 OAuth/Supabase 回调。
- 迁移时先让旧域名和新域名并行，强制主页仍使用 `jackyun.top`，直至新域名 HTTPS、登记接口和后台全部验证。
- 新域名稳定一个发布周期后，再更新 TR3000 URL；最后才将旧域名做 308 跳转。
- 阿里云侧优先使用受管 HTTPS、只开放 80/443，不开放 TR3000 管理端口。
- 数据库迁移先做备份与恢复演练；切换期间保留旧 Supabase 只读回滚路径。

## 回滚

- TR3000：取消接口勾选或关闭强制主页，恢复原 URL；不要删除已有 QoS 规则。
- 站点：回滚到上一部署，登记页返回维护提示。
- 数据库：新表独立，不修改现有业务表；回滚站点不会影响现有用户数据。
