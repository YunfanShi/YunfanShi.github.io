# 公告系统（3.20.0）

在「管理后台 → 公告」创建或编辑公告。分类包括公告、更新、BUG / 故障、维护、新功能和活动；优先级包括普通、重要和紧急。置顶公告优先，之后按优先级和创建时间排序。

显示范围可选择全局或多个功能页面。指定 /schedule 时，仅在 Schedule 页面及其子页面显示；不会匹配 /scheduler。预设页面之外可填写站内路径。页面范围同样用于用户通知中心的未读与历史列表。工单私信沿用独立收件人权限。

展示方式包括页面横幅、弹窗和仅通知中心。横幅位于顶栏下方，可关闭且不会阻断操作。关闭后保存用户已读记录，不会反复弹出。通知中心的「历史」可以查看当前页面和全局的已发布公告，包括已读及过期记录；后台的「历史 / 停用」保留过期或已停用公告。

维护和故障可设置排查中、已定位、观察中及已恢复状态，并附站内路径或 HTTPS 操作链接。恢复后编辑原公告，勾选「重新提醒已读用户」：保存时增加提醒版本并重置数据库已读记录，让用户收到恢复信息。普通编辑保留已读状态。

开始／结束时间按浏览器本机时区输入，保存为 UTC。留空表示立即生效／长期有效；开始时间之后展示，结束时间之后自动停止，用户端每分钟刷新公告。后台可在保存前预览正文、分类、链接及某个页面是否在范围内；预览不写入数据。

数据库迁移：supabase/migrations/20261006131058_announcement_categories_and_page_delivery.sql。旧记录默认全局、普通级别和「公告」分类，原有 notice/message 投递保持兼容。管理员写入仍通过受保护的 RPC；普通用户无法通过数据接口提前读取未发布的公共公告。

验证：npm run test:sync 包含公告逻辑和管理端交互回归；tests/announcements.sql 在事务内验证字段、已读保留、恢复提醒、输入校验和 RLS，测试数据全部回滚。
