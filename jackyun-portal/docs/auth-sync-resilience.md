# 退出登录与数据库故障处理

退出菜单提供普通退出和强制退出。普通退出先保存本地备份并尝试同步，存在待上传修改时提供强制退出选项，再尝试撤销当前 Supabase 会话；强制退出只清除本站认证 cookie，不请求 Supabase，因此已删除设备、认证服务故障不会阻止退出。不会撤销其他设备，也不保证服务端旧访问令牌即时失效。

两种退出均保留本地学习数据、同步队列和离线操作，清除 Service Worker 用户缓存。同账户重新登录后可继续同步；不同账户不得接管原账户待上传数据。共享设备仍应注意本地数据隐私。强制退出不表示未上传的数据已经备份到云端。

Supabase 和同步 fetch 的单次网络等待上限为 8 秒，使用 AbortSignal 合并调用方取消信号。SDK 可能自行重试，所以完整业务流程不等于 8 秒。数据库故障时页面已有的默认值/错误边界继续负责降级，受保护的管理页面不会绕过认证。

闲置同步 tick 只检查本地变化；没有待上传修改时不访问数据库。进入页面、焦点恢复、联网和手动同步仍会拉取云端变化。代价是持续停留在同一页时，其他设备的新数据不会每 30 秒自动拉取。同步失败后自动重试间隔为 30、60、120、240、300 秒，成功后重置；401/403（含设备撤销）暂停自动同步，用户可在同步中心手动重试。本地变化仍继续进入队列。没有新增定时健康检查。

## Supabase 再次无响应时

先查看 Supabase 状态页与项目 Observability 的 CPU、内存、磁盘 I/O、连接数，以及 Database Connections 的阻塞会话和 Query Performance。保存故障时间和日志，再按证据处理慢查询、锁或资源耗尽。应用超时/退避可减少故障放大，但不能修复数据库自身卡死。重启可恢复服务，却不能证明根因已经消除；平台级故障或反复无响应需联系 Supabase 支持。不要自动重启数据库，也不要清空本地同步队列。

## 2026-09-27 登录续期排查

已修复 Proxy 会话刷新后仍向下游传递旧 Cookie 的问题：先更新请求 Cookie，再重新构建 NextResponse，并在重定向和 503 响应中保留会话 Cookie。账户状态和访问拒绝页面的普通退出限定为当前设备；删除账户仍撤销全部会话。后台导航禁用预取，避免未打开页面提前触发认证与数据库查询。

验证：`node --test tests/auth-session-cookies.test.mts` 覆盖请求头续期、多个 Cookie 批次、旧分片清除，以及认证失败、授权查询失败和各重定向分支。修复前 8 项失败，修复后通过。

故障证据：用户提供的 Supabase 导出覆盖 UTC 2026-09-26 21:27 至 2026-09-27 02:21（北京时间 05:27 至 10:21），1000 条导出记录中包含 660 条令牌请求 503/504、79 条 SQL statement timeout。这是导出样本，不能据此计算全站请求量或故障率。实时 Auth 日志同时存在 PostgreSQL 连接失败、刷新超时和并发刷新冲突；只读数据库诊断也连接超时。Vercel 导出覆盖 UTC 02:04 至 02:23，含 14 条超时错误和 HeadlessChrome 页面访问，不能代表整晚流量或证明攻击。

结论：数据库/认证服务可用性异常与应用续期缺陷同时存在。尚无证据确定数据库故障属于 CPU、内存、I/O、连接耗尽、锁等待或平台维护。恢复后应检查项目 Observability 及慢查询/锁统计；若持续无法连接，将故障时间和日志提交 Supabase 支持。代码修复不能替代数据库故障处理，真实多设备隔夜登录仍需验证。

## 重复 Schedule 分片下载

进一步核对 UTC 2026-09-26 18:00–20:00 的网关日志：4853 次 legacy_sync_data 表读取中，4507 次是大数据下载端点按分片读取同一 Schedule 全量值，345 次是 v2 增量读取。表名不等同于旧 `/api/legacy-sync` 接口。

发现反馈循环：pull 对未变化记录也派发云端应用事件，Schedule 重载并派发编辑事件，编辑回调又执行全量同步；相同 revision/hash 的大数据没有跳过下载，每个分片再次读取整个数据库值和认证用户。

修复：本地副本完整且 revision/hash 相同时跳过记录；仅在实际存储内容改变时通知页面；Schedule 相同内容不重复保存或发送编辑事件；编辑触发仅在存在 outbox 修改时访问云端。进入页面、焦点恢复、联网和手动读取仍正常拉取；本地副本丢失或远程版本变化时重新下载，不丢弃待上传数据。

回归测试执行实际 pull 函数：同一大记录重复返回 100 次，分片下载与页面通知均仅发生一次，重建内容完全一致。生产流量下降仍需部署后验证，不能单凭单元测试断定数据库已恢复。

## 空闲休眠

默认空闲 30 分钟进入休眠，设置 → 常规 → 空闲休眠可选 5 / 15 / 30 / 60 分钟或关闭。配置沿用现有本地存储云同步。键盘、触摸、滚动与同源旧版 iframe 内的操作重置空闲计时；切换可见性本身不算用户操作。

休眠先等待正在运行的同步，再持久化同步队列并尝试上传；随后等待本地备份完成，最后暂停自动同步及 Supabase 自动令牌刷新。云端失败保留队列并显示待上传数量，本地备份失败则不休眠。保存期间继续操作会取消本次休眠。再次操作自动唤醒，恢复刷新与同步，不主动退出账号。

保存范围为已有自动保存内容、同步队列和支持备份的本地页面数据。未接入自动保存的表单、跨域嵌入内容及服务端运行中的任务不属于此机制；计时器和音频不因同步休眠而停止。休眠按浏览器标签页管理。后台浏览器可能延迟计时器，恢复执行后检查实际空闲时长。

验证：workspace-idle.test.mts 覆盖 30 分钟边界、重复 tick、保存中操作、禁用、本地保存失败，以及等待正在运行和已排队同步。

## 登录保留与服务器故障提示

认证 SDK 当前版本对部分 HTTP 500 刷新错误按不可恢复错误处理，并清除会话。统一请求适配器将 Auth 接口 5xx / 408 / 429 交给 SDK 的可重试路径，保留原刷新令牌；网络中断和超时也沿用此路径。明确的令牌失效、撤销及用户主动退出仍按原流程处理，不保存或重放密码，不用缓存身份绕过权限校验。

登录页自动验证已有会话；服务不可用时按 30 秒至 5 分钟的退避重试，联网、重新切回页面或休眠唤醒时也会尝试恢复。页面隐藏或休眠时不发起恢复请求。服务恢复且会话验证成功后自动跳转到目标页面。服务端因临时认证故障只能显示本机模式时，页面也提供恢复提示，并在验证成功后刷新服务端状态。

ID 查询失败、认证失败和当前密码验证失败分别分类，只有明确 invalid_credentials 才显示账号或密码错误。常见错误展示 SERVICE_UNAVAILABLE、REQUEST_TIMEOUT、RATE_LIMITED、SESSION_EXPIRED 等可识别代号；不直接输出数据库 SQL、令牌或内部异常。注册、密码操作及第三方登录沿用分类提示。同站浏览器请求的服务器故障复用现有故障横幅。

回归验证使用真实已安装 GoTrueClient：原始 HTTP 500 清除会话；适配器保留旧令牌；服务恢复通过刷新令牌恢复登录；撤销令牌仍被清除。另覆盖 ID 数据库查询超时与真正凭据错误的区分。
