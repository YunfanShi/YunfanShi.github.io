# 同步流量修复（3.19.3）

大数据下载原来每返回一个 60 KB 分片，都从 Supabase 读取整条记录。
计划表实测 JSON 为 1,587,071 字节，共 27 片；重复读取会放大数据库出站流量。

新查询在 Postgres 内按 UTF-8 字节切片，再返回 Base64。同步列表在数据库内
省略大数据内容，只返回版本和 large 标记。保留现有浏览器协议、版本检查、
用户隔离和上传流程，不修改用户已有记录。

## 发布

先应用迁移 `20261006072459_reduce_sync_egress.sql`，再部署网站接口。
该迁移已应用到当前云端项目；旧网站可继续工作，但只有部署新接口后才能减少流量。
数据库函数使用 SECURITY INVOKER，沿用 RLS，只允许 authenticated 调用。
没有旧查询回退，避免缺少迁移时悄悄恢复高流量读取。

已消耗的月度流量不会因修复退回；本次修复也不解除平台额度限制。

## 验证

- `npm run test:sync`：33 项通过。
- TypeScript、生产构建及修改文件 ESLint 通过。
- 全仓库 ESLint 有 16 个既有错误，位于本次未修改的页面和测试文件。
- `supabase/tests/sync_egress.sql`：真实数据库回归测试，以两个现有用户创建事务内临时数据，
  验证多片中文和表情拼接、数据隔离、错误版本、非法分片、匿名权限和列表游标；
  最后回滚全部测试记录。需要管理员 SQL 会话及至少两个现有用户。
- 真实计划表首片数据为 60,000 字节，含 Base64 的响应为 80,054 字节，
  列表记录为 310 字节。完整下载的数据库响应流量估计由约 43 MB 降至约 2.1 MB；
  此估计不含认证请求、上传及其他接口。

网站的实际同步错误尚未复现，不能仅凭这些测试认定用户端已恢复同步。
